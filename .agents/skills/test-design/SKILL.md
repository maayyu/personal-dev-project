# test-design｜仕様根拠からテストケースを設計

## 目的・担当範囲

- 実装を正しいと仮定せず、仕様を満たすためのテスト観点・ケース・期待結果を設計する。
- リポジトリルートの `AGENTS.md` に従う。
- このSkillは**テスト設計専用**。モードに関係なくファイル変更・テスト実行・Gitの変更操作はしない。実装が必要な場合は `test-implement` 等の別作業として扱う。
- 少数の重要なケースから始め、ユーザーの目的に合わない網羅的な列挙はしない。

## 入力

- **テスト対象**：機能・メソッド・Entity・Repositoryなど。
- **対象範囲**：正常系、異常系、境界値、DB制約、競合など（任意）。
- **根拠資料**：関連する確定仕様・基本設計・詳細設計、既存のテスト方針。
- **現在地**：対象ブランチ・既存テストの状態。指定がなければ `AGENTS.md` §3に従い、現在のブランチと関連記録から調べる。

## 手順

1. **仕様と現在地を確認する**
   - `AGENTS.md` §3に従って、対象ブランチの確定仕様・DDL・関連実装・既存テストを確認する。現在のブランチと対象実装ブランチが異なる場合は、切り替えず必要な版を読み取る。
   - 参照した根拠にはパスとブランチ・コミット（確認できる範囲）を示す。どのブランチの内容か不明な資料は正本と断定しない。
   - 仕様の正本とコード・テストの現在の振る舞いを区別し、後者だけから期待結果を作らない。基本設計・詳細設計・実DDLの確認漏れによる「未確定」判定を避ける。
   - 参照できなかった資料・別ブランチの未確認変更と、仕様自体が未決定である場合を明確に区別する。
2. **責務に応じてテスト層を決める**
   - Entity等の状態変更・純粋なロジックは、可能な範囲で単体テストを検討する。
   - JPAマッピング、制約、採番、DB生成日時、トランザクション等は、必要に応じてTestcontainersのPostgreSQL実DBテストを検討する。
   - Serviceの業務判断、APIの入出力、権限、競合などは、対象機能の責務と実装段階に合う層で扱う。
   - 上位レイヤーのテストを今回の範囲に無理に混ぜない。
3. **ケースを整理する**
   - 正常系、異常系、境界値、所有者・整合性・制約等のうち関連するものを選ぶ。
   - 各ケースに「条件／操作／期待結果／根拠／適切なテスト層」を対応付ける。
   - 既存テストは現在のブランチだけでなく、特定できた対象実装ブランチでも確認する。両方を確認できない場合、「新規テストが必要」と断定せず未確認とする。
   - 既存テストのコードで扱う範囲と、新規に必要な範囲を区別する。テストの存在と実行成功・保証内容は別に扱う。
   - テストを通すことだけを目的に期待値を弱めたり、既存テストの無効化を提案しない。
4. **実装可能性と優先順位を確認する**
   - 使用するテスト基盤・前提データ・環境（例：Docker／Testcontainers）を確認する。
   - 前提不足や仕様不明で期待結果を決められない場合は「要確認」とする。ただし、資料未発見・参照不可は「資料未確認」と区別する。重要な確認事項は最大3件に整理する。
   - 学習価値と不具合検知効果の高いケースを先に、重複ケースはまとめる。
   - 対象外のRepository・Service等の検証は後続作業として短く触れるにとどめ、今回のケース表を勝手に拡張しない。
5. **実装への引き渡しを作る**
   - ユーザーがJUnit等でテストを書けるよう、実施順序・テスト名の候補・準備データを必要な範囲で示す。
   - このSkillではテストコードやファイルを生成せず、テストを実行したと報告しない。

## 出力形式

1. **対象・仕様根拠**：何を保証するか、対象ブランチ、参照したファイルのパスと版、未確認の前提。
2. **テストケース表**：優先度／テスト層／条件・入力／操作／期待結果／仕様根拠。簡単な対象なら箇条書きでもよい。
3. **実装の順序**：重要なケースから着手する手順と、必要なテスト基盤。
4. **要確認・対象外**：未決事項、今回扱わない上位機能、既存テストとの役割分担。

根拠が不十分なケースには明示的に「暫定」「要確認」を付け、実際に成功・失敗したと主張しない。

## 完了条件

- テストケースの期待結果が、仕様の根拠と対応付いている。
- 単体テストとDB実テスト等の役割が明確で、重複や責務逸脱がない。
- 次にユーザーが書くテストを選べる。
- ファイル変更、テスト実行、Gitの変更操作はしていない。
